## Protocolo acotado de Android

1. Esperar confirmación del responsable de que el host está libre de builds. Un solo operador de `emulator-5590`; verificar primero serial y nombre exacto `Dailoop015_Final_API37`. Conservar sus datos sintéticos y el APK/hash instalado. No usar dispositivos implícitos ni reiniciar el servidor ADB compartido.
2. Para comparación, usar APK 0.1.5 C6 y candidata en el mismo AVD, GPU, resolución, densidad, fontScale, modo de energía, escalas de animación y fixture 10/100. Registrar la carga del host; una interrupción externa invalida ese recorrido, no se oculta. Sin Metro ni compilaciones de Dailoop simultáneas. El AVD software no certifica el S26 ni 120 Hz.
3. Registrar el primer Inicio → Estadísticas después de un reinicio de proceso (sin borrar datos), separado del calentado. Luego 20 cambios alternos Inicio ↔ Estadísticas y cuatro cambios Inicio ↔ Historial. No convertir la duración completa de comandos ADB/Maestro en tiempo de la app.
4. Si el dispositivo admite captura fluida, usar `screenrecord` con el marcador de toque del sistema. Guardar el vídeo original y los timestamps reales de sus cuadros, obtenidos con `ffprobe`; nunca inferirlos solo de `r_frame_rate`. Anotar el primer cuadro que muestra el marcador y el primer cuadro con contenido útil de destino (título, período y cifra para Estadísticas; búsqueda y filas para Historial), no solo el indicador seleccionado.
5. Esa diferencia se llama **latencia visual observada en la grabación**, con cuantización de cuadros y coste del recorder explícitos. El marcador también se dibuja: no prueba el instante físico exacto de contacto. Si faltan cuadros, el marcador no aparece o hay duplicados ambiguos, conservar el vídeo como INCONCLUSO y no publicar p50/p95 inventados. Una traza input/FrameTimeline puede explicar el pipeline, pero necesita correlacionarse con contenido para demostrar la llegada semántica a Estadísticas.
6. Resumir primer acceso y p50/p95 calentados, más número de muestras válidas y resolución temporal. Criterios heredados: feedback <100 ms y p95 de contenido útil ≤200 ms en el dispositivo medido. No rebajar esos objetivos si fallan; 120 Hz / 8,33 ms sigue pendiente en el S26 físico.
7. Regresión funcional breve: búsqueda/filtros retenidos, Stats mes/selección/reporte/volver, arrastre de barra, arrastre del contenido que no navega y scroll vertical, extremos, reversión rápida, modal sucio + teclado, detalle/atrás, un registro intencionado. Exportar backups reales antes/después para comprobar la ausencia de duplicados. No repetir restauración/reportes completos ya validados si el cambio no afecta esa frontera.

Las opciones y límites de grabación vienen de [ADB](https://developer.android.com/tools/adb#screenrecord), y el marcador de [opciones de desarrollador Android](https://developer.android.com/studio/debug/dev-options#input). [FrameTimeline](https://perfetto.dev/docs/data-sources/frametimeline) describe el pipeline de presentación y la posibilidad de cuadros fluidos que se presentan tarde; por sí solo no identifica qué contenido de Dailoop aparece.
